# Security Model

## Trust boundaries

The Git bus is an untrusted input channel even when the repository is private. Remote task data is validated before it influences local paths, Git operations, or agent prompts.

## Remote task restrictions

A task cannot select or override:

- local repository paths;
- Git remotes;
- executables or shell commands;
- Airelay binary, profile, session key, resume ID, or launch arguments;
- environment variables;
- local API address;
- approval state;
- timeout or repair policy.

These values exist only in owner-controlled local configuration.

## Filesystem restrictions

All remote paths are normalized relative paths beneath one task directory. Symlinks in copied task payloads are rejected. File sizes and aggregate task size are bounded. Local agent report paths are generated by the gateway.

## Git restrictions

- source checkout must be a Git worktree with the expected `origin` repository identity;
- target base must be an exact 40-character commit SHA;
- task branches must use the `agent/` prefix;
- work is isolated with `git worktree`;
- backup refs are created before patch application;
- no `git stash`, `git clean -fd`, force push, or source-checkout reset is used;
- rollback removes only the task worktree and task branch after resetting it to the stored backup ref.

## Process restrictions

The HTTP API binds to loopback. Airelay launch and prompt arguments come only from local config plus generated paths. Detailed instructions are written to files to avoid shell quoting and prompt-length hazards.

`--dangerously-bypass-approvals-and-sandbox` is a local owner policy for a trusted host session. The gateway never accepts it from GitHub task data.
